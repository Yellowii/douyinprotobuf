# 本地登录配置验收

日期：2026-10-08。新增工作台“保存登录态”，浏览器与 WSS 新连接均从本地配置重新读取 Cookie。

## 保存与恢复

- Cookie 写入 `.env` 的 `DOUYIN_COOKIE`，保留其他变量；完整抖音 Cookie 属性与本地存储写入 `.browser-profile/login-state.json`。
- 从同一次浏览器快照生成两份配置，避免登录续期导致 Cookie 与浏览器状态不同步。配置写入采用独立临时文件；`.env` 替换失败时恢复旧浏览器状态，首次失败则移除新状态。
- 手动修改或清空 `.env` Cookie 后，旧浏览器状态不会覆盖新值。损坏的状态 JSON 不阻碍从 `.env` 读取 Cookie。
- 保存请求沿用本机 Host、Origin、工作台令牌与操作串行保护。API 和 SSE 仅返回保存时间、是否已配置等元数据，静态路由不提供配置文件。两个配置路径均被 Git 忽略。

## 验证范围

完整 `npm test`：40 项通过，0 失败，0 跳过。登录功能五项测试通过，格式检查及双协议产物验证通过。

五项登录测试覆盖真实 Chrome 保存及恢复、抖音来源筛选、精确 Cookie 值与 HttpOnly 保留、配置动态读取及清空、快照期间 Cookie 刷新、写入失败回滚、接口授权和静态路径隔离。

其中工作台端到端测试通过真实浏览器、页面表单与“保存登录态”按钮写入配置，关闭服务后重新启动并恢复同一 Cookie；页面和接口均不出现 Cookie 值。仅直播站点网络响应替换为本地测试页面，未请求公网，也未使用真实账号凭据。

真实账号登录是否仍有效取决于平台会话期限与验证要求；测试证明本地保存、读取与恢复链路，不将配置存在等同于平台当前已登录。
