# 账号监测与登录态保存修正

日期：2026-10-08。

## 调查结果

保存文件与配置 Cookie 的摘要一致，浏览器可恢复相同 Cookie 属性与本地存储；诊断未打印 Cookie 内容。保存的配置缺少常见账号会话标记，不能据文件存在判断账号已登录。运行中的 WebCast 日志同时有成功解析的弹幕、入场和房间消息，账号状态与消息流应独立检测。

旧版允许将任何抖音 Cookie 保存并提示“已保存登录态”，容易把访客状态与账号登录混淆。现显示“会话配置已保存”，以官方当前用户接口确认登录。头像、昵称、抖音号和 UID 仅从当前用户响应提取；不从主播、聊天用户或第三方页面推断当前账号。

## 实现与验证

- 观察官方页面 `/webcast/user/me/` 和 `/aweme/v1/web/user/profile/self/` 响应。主动查询动态发现已加载 SDK 的当前用户函数，复用官方请求参数和签名；每分钟定时查询，人工查询至少间隔 15 秒。
- 保存之前等待冷却并进行新的官方账号确认，不复用过期缓存；未登录、检测失败或浏览器关闭时保留原配置。等待和查询结束均核对会话代次，关闭后不会卡在检测状态。
- 兼容 SDK 对象与 JSON 字符串响应，未加载的模块不会阻止搜索其他候选。头像限 HTTPS 抖音图片域，账号展示采用文本节点；API/SSE 不输出 Cookie、会话令牌或完整原始响应。
- 真实 Chrome 测试覆盖访客→登录→头像/昵称/抖音号/精确 UID 展示、手机无横向溢出、访客保存被拒绝、重启恢复 Cookie、查询限频、缓存账号不能放行访客保存、查询等待期间关闭浏览器。
- 真实官方首页验证成功定位当前用户函数；当前本地会话的官方查询响应不可解析，明确显示检测失败，未将其误标为已登录。真实账号仍须由用户在采集浏览器完成登录/验证，账号资料显示取决于官方接口实际返回。

官方 SDK 依据为当前官方资源 `client-entry~1.cf6f9f0d.js`；实现不固定模块编号。该资源由 `https://live.douyin.com/` 引用，源码为 `https://lf-webcast-platform.bytetos.com/obj/webcast-platform-cdn/webcast/douyin_live/client-entry~1.cf6f9f0d.js`。当前账号接口仅用于读取本人信息，不提供互动写入或登录绕过。

完整测试：40 项通过，0 失败，0 跳过；双产物验证及格式检查通过。
