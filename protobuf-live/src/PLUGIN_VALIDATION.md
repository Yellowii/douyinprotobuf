# 基础展示插件与官方样式验收

日期：2026-10-08。用户选择接入弹幕、礼物、显示工具。新增工作台互动预览，使用本项目展示适配器和官方下载的两份原始 CSS；未执行原始官方业务插件 JS。

## 接入内容

- 滚动弹幕，包含文字、表情/语音文字提示、屏幕及特权弹幕。
- 礼物托盘，普通礼物与 `BindingGiftMessage.msg` 嵌套礼物都可展示，点击保留完整原消息结构。
- 开关、暂停、清空、字号、速度、透明度、全屏，显示设置在浏览器本地保存。
- 官方 CSS 位于 `static/vendor/`，源 URL 和 SHA-256 位于 `provenance.json`，内容摘要逐文件核验一致。CSS 在 Shadow DOM 内使用，静态资源通过固定路径白名单提供。
- 新任务有独立会话标识，避免跨任务礼物去重；单会话重连不会清空去重。消息正文使用文本节点，不转为 HTML。

## 验证结果

新增三项真实 Chrome 验证均通过：

1. 从真实本地 raw 监听 → 官方 Parser → SSE → 页面显示弹幕与礼物；恶意 HTML 字样按文本展示。暂停期间消息仍解析且进入完整消息流；键盘 Enter 可选择弹幕 JSON；全屏、设置刷新恢复和 390 像素手机布局通过，暂停后改变窗口尺寸，已显示弹幕仍位于预览区域。输入 200 条预览时节点限制为 40 条弹幕、3 张礼物卡。
2. 使用官方 Parser 解码绑定礼物，验证用户、礼物名、数量；默认 `repeat_count=0` 能回退到有效 `combo_count`，`9007199254740993` 精确显示，晚到的小计数/重复通知不相加、不回退。64 位测试遵守实际有符号字段范围。
3. 同目录经页面表单连续启动两次批量任务；第一批礼物自然到期后，第二批同消息 ID 仍能重新显示。

`npm run verify`：2,726 个消息、15,391 个字段、1 个可枚举 enum，两类协议产物通过验证。`npm run format:check` 与 `git diff --check` 通过。

运行中的 8787 工作台另经真实页面解析 6 个合成包，显示 5 条弹幕与 1 张累计数量 5 的礼物卡；945 像素全屏预览及 390 像素手机布局通过。页面错误与 CSP 违规均为 0，截图已在本地检查。

此验收使用合成样本和本机 Chrome，未为本功能额外连接抖音直播服务器，未改写外部 rawproto 目录。真实消息结构仍以当前官方 Parser 和原始 JSON 为准；本预览不提供视频播放、支付、礼物资产动效或平台鉴权能力。
